# 05. 설치와 현장 시험

2026-11-06 밤. PR #1을 올린 뒤 새 빌드를 이 Mac에 설치하고, 구버전이 설치된 원격 Mac과 실제로 연결해 동작을 확인했다.
시각은 모두 현지 시각이다. 기기 ID, 호스트 이름, 사설 IP는 공개 저장소라서 적지 않는다.

## 1. 결과 요약

- 새 빌드를 설치했고, 설치 직후 **동기화가 멈추는 문제**가 생겼다. 원인은 Keychain 허용 창 하나가 승인되지 않아 이 Mac의 신원 키가 새로 만들어진 것이다 → [이슈 03](../issues/03-keychain-identity-reset-on-reinstall.md).
- 앱을 재실행해 Keychain 창을 "항상 허용"으로 승인하고 재페어링하자 **동기화가 작동했다.** 원격 Mac의 한/영 전환 7번이 같은 초에 이 Mac의 입력 소스에 반영되었다.
- 재페어링 중 구버전 원격에서 HTTP 429 오류 창이 한 번 떴으나 페어링은 완료되었다 → [이슈 04](../issues/04-pairing-error-dialog-on-ntfy-429.md).
- 이번 시험은 **새 빌드(로컬) + 구버전(원격), 같은 네트워크(Bonjour 직접 연결)** 한 가지 구성이다. Tailscale 경로와 주소 교환은 시험하지 못했다.

## 5. 정정과 도구의 한계

- **"앱에 연결이 하나도 없다"는 초기 판단은 틀렸다.** `lsof -a -p <PID> -i`가 이 환경에서 일부 소켓(ESTABLISHED)을 보여 주지 못했다. `netstat -anv`는 소유 프로세스와 바이트 수를 보여 주어 이를 바로잡았다. 이후 연결 확인은 `netstat -anv`를 기준으로 했다.
- `strings`는 ASCII 문자열만 찾아 한글 문구는 0개로 나왔다(구 문구·새 문구 모두). 한글 문자열은 `LC_ALL=C grep -a`로 직접 검색해야 한다.
- zsh에는 내장 `log` 명령이 있어 통합 로그 조회는 `/usr/bin/log`를 써야 한다.
- 창 목록 도구(`CGWindowListCopyWindowInfo`)는 알려진 앱(Screen Sharing)에서 창이 보이는지로 먼저 검증한 뒤 썼다.

## 7. 미해결·미확인

- **이 Mac의 신뢰 목록이 23:4x에 잠시 0개로 보인 이유를 확인하지 못했다.** 자동으로 찾기 직후의 상태이며, 사용자의 "기기 삭제"·"모든 페어링 초기화" 조작이 있었는지는 알 수 없다. 코드에는 신뢰 목록을 자동으로 지우는 경로가 없다.
- 같은 시각에 이 Mac의 `UseTailscalePath` 값이 이전 확인(꺼짐)과 달리 켜짐으로 관측되었다. 변경 경위는 확인하지 못했다.
- 이번 시험에서 Tailscale 직접 경로, 주소 교환, 다른 네트워크 구성은 시험하지 않았다.
- 이 Mac을 재부팅한 뒤 Keychain 창이 다시 뜨는지 확인하지 않았다.
- 원격 Mac은 구버전이라 그쪽의 Tailscale 재실행 문제(Issue #2)는 남아 있을 수 있다. 원격에 새 빌드를 설치할 때는 Keychain 창을 모두 승인해야 신원이 유지된다.
- 이슈 03의 `loadOrCreate` 결함은 수정하지 않았다.
